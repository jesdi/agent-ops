Stage and park

A task has two independent properties.

  • The stage tells where the task is in the pipeline: spec, plan, implement, and so on.
  • The park tells whether the task waits for something. An empty park means the task is not parked.

A parked task keeps its stage. A park ends the session and gives back the capacity and the E2E slot. The login park is the only exception: its session stays alive, because the operator types the login code into it.

The dispatcher does not watch sessions all the time. A timer starts one pass each 10 minutes. Each pass reads the state of each task and does the next step. Thus a state change can show up to 10 minutes after its cause.

Stage signal

A session tells the dispatcher its state through the file .agent/stage.json in the task's worktree. The dispatcher reads the status field on each pass.

Turn end

When a session ends a turn, a hook in the worktree (.agent/stop-hook.sh) sends one ping to the waitd service. waitd writes one marker for the task. The next pass reads the marker.

flowchart LR
  T([Session ends a turn]) --> R{Runtime}
  R -->|Codex| W[waiting marker:
if the signal is working, the next pass parks the task]
  R -->|Claude| S{Signal is working, and
background work is running?}
  S -->|no| W
  S -->|yes| B[background marker:
the task stays in progress]
  • Background work is a background shell or a background agent that the session started and that is still running at the turn end.
  • Only Claude sessions report background work. A Codex turn end always writes a waiting marker.
  • Both markers are removed when a session ends and when the task changes stage, so a new session never gets the markers of the old one.

  • The pass asks herdr (the session layer) for the agent's status. working is never idle, however long the turn is.
  • During a background wait the stall timer does not apply. The 3-hour clock starts again only when a turn end reports background work that the turn end before it did not report.
  • When herdr cannot be asked, the pass does nothing and tries again on the next pass.
  • The two limits are settings: stall_after_seconds (600) and background_wait_seconds (10800).

Round caps

Some loops can run only a fixed number of rounds. When a loop reaches its cap, the task parks for input. A round that an implement session reports is never counted: its skill has its own limits. The loop_caps setting in targets.yaml changes the numbers.

LoopCapOne round is
review2One fix round in the review stage.
gate2One gate-loop round that a session reports.
e2e3One failed end-to-end run in implement or review.
ci3One fix on an open PR: a red check, a conflict or a failed run.

Review rounds at the plan gate

The task waits at awaiting-plan-review with an approval request for one plan: the review summary and the ticket files as they were when the request was made.

  • Signal working at the gate removes the request. The session changes the plan, and the old summary must not be approved.
  • The next signal awaiting-review starts a new review round: the dispatcher checks the ticket set again, publishes the spec folder, sends a new notification and starts the 15 minutes again.
  • A new round also starts when the summary or a ticket file changed and no pass saw the signal working.
  • With no action from the operator, the task has a budget of two steps. A new review round uses one step, and a new start of a stopped plan session uses one step: the two kinds share the budget. When the budget is used, the next step parks the task for review. A reply from the operator gives the full budget back, and the round that answers the reply uses no step.

Known limits

  • A waiting marker is not compared with the live session. If a session ends a turn and starts a new turn before the next pass, the pass can park a session that is working.
  • Codex sessions have no background wait. A Codex session that ends a turn while background work runs is parked.
  • A parked task does not start again by itself. Only an operator reply or resume, a completed CI run, or a spec approval ends a park.
